# Local game deployment of the R3 strategies

This deployment fork targets combined patch **1.4.5**, with the six **v3** cash-management and industry-completion strategies. `Host/` comes from `src/BrassHost`; `Policy/` comes from `src/BrassLegacyAI`. Search policy, host and embedded profiles retain their previous bytes; the deployment adds difficulty contracts and extends `LocalGameState`. The independent research directories and frozen banks retain their recorded identities and qualification.

The [1.4.5 menu initialization repair](../../docs/AI_MENU_INITIALIZATION_1.4.5.md) includes inactive parents when finding the custom menu and attaching row controls. Native regression tests now invoke the real controller while the cached view is still disabled, matching production routing. `qualify-menu-initialization-release.ps1` verifies the two-lookup source scope and fresh menu evidence while retaining 1.4.4's unchanged gameplay/runtime qualification.

The shipped DLL is `BrassLegacyAI.dll`, with a one-way dependency on `BrassPatch.dll`. `scripts/build-patch.ps1` first builds all existing rules/UI repairs from the verified stock binary, then calls `scripts/build-local-ai.ps1` to embed six S1 v3 profiles plus six original v2 compatibility profiles and weave an explicit 28-method menu/turn/input allowlist. No external service, Python runtime, neural weights, `live.json`, or mutable profile file is needed when playing.

The deployment observation contract is `local-game/0.3.0`; its rules identity is `steam-brass-patch-1.3.0`. Two, three, and four players, non-contiguous player colors, and introductory games have explicit configuration, card composition, wildcard counts, round limits, and final scoring. Policy observations contain the acting player's hand and public information. Worker tasks never receive the live game, another player's hand, or the live RNG.

`ProfileCatalog` defines the six actual strategies. The menu adds Random, which independently resolves to one concrete profile per bot at creation, without consuming the game RNG. The chosen style supplies bounded preferences; persistent intent adapts to opportunities and falls back when its plan becomes infeasible or stalls. New games default to Balanced v3. Existing v2 saves keep their original bytes and identities; `ForPlay` enables the v3 cash policy on a detached execution copy. `AiSetupRow` and `StrategyPicker` provide direct selection, a larger-catalog filter and separate per-seat Easy/Mid/Hard controls. `DifficultyCatalog` defines their 2,000/5,000/12,000 ms allowances; a new setup defaults to Hard. Existing local-AI saves retain 10,000 ms compatibility. Every custom bot still uses the engine's `AIType.Hard` routing marker.

The bank's `work_limit` remains 240 and `reply_work` remains 2,048; first/second action widths, beam and style parameters are unchanged. V3 adds complete-turn payment protection, bounded recovery incumbents and a soft reserve preference at the borrowing floor. Initial preparation is excluded from the search clock; both actions and replanning share its remaining time. Each planning request has its own node counter and can perform bounded legal completion after exhaustion, so 240 is not an absolute aggregate node ceiling across replans. The time presets are deployment settings and do not modify frozen research profiles or establish calibrated strength tiers. S2 research variants are not selectable.

The six embedded **v2** resources exactly match H5's `bank-804c85204da65824cb9b`. V3 resources differ in ID and the explicit cash/conversion-policy flags; the separately admitted v3 bank is recorded in `docs/LOCAL_AI_V3_CONVERSION.md`. H5's admitted strategies remain S1 v2. `tests/BrassLocalAI/verify-h5-provenance.ps1` verifies source/runtime preservation, admission records and both generations' embedded profile hashes; it is required by release qualification. Add `-Installed` to check the actual game DLL. The fork's supported configurations, live timing and runtime identity remain separate from the original frozen four-player worker. Do not use deployment v3 JSON with that older worker; it does not implement the new cash policy.

`LocalMenu` binds setup selections to player metadata reference identity. At creation, `LocalGameState` freezes the color/sitting-order mapping, complete profile parameters, and source/deployment hashes. It stores this with revision- and event-prefix-bound per-seat intent in the `brasspatch_ai` JSON metadata extension. New games use format `brass-local-ai-save/1.1.0` and assignment-hashed `local-ai-execution/1.0.0` difficulty objects. The reader validates exact ID/time pairs and preserves format 1.0.0 with **Existing · 10s** compatibility. Difficulty stays separate from frozen profile/intent identity. All fields share the existing checksummed events/metadata save transaction; there is no second sidecar writer. Metadata-only writes, loading and cloning preserve the extension. Old saves without it keep their original AI and appear as **Original AI**.

New game creation retains previous save directories. Continue selects the newest ready, unfinished game; a partially created game is never offered. Corrupt or incompatible saves produce a visible error and remain intact. No migration of old experimental AI sidecars is attempted.

`LocalTurnBridge` captures a detached observation on the main thread, searches asynchronously, validates each complete action in isolation, then commits once on the main thread. A second action runs on a later frame. Generation, instance, revision, actor, request, profile, and contract guards prevent stale work from applying. Play now is removed and its callback is inert. `TurnInputGuard` rejects human action/card/board input during a strategy bot's turn blocks action input while viewing historical states, and prevents replay skipping from replacing an actively planned game. It leaves the human board-building permission intact. End-turn, save, debt, and subsequent presentation use the existing patched game flow. Game replacement, history navigation, menu return, and destruction cancel work; simply hiding the panel does not.

See `tests/BrassLocalAI/`, [the 1.4.4 style/difficulty release note](../../docs/AI_STYLE_AND_DIFFICULTY_1.4.4.md) and [the 1.4.2 release note](../../docs/PRESENTATION_SAVE_1.4.2.md) for current settings, repairs, compatibility and verification limits. `qualify-ui-release.ps1` requires the 108 native configurations, UI rendering/input checks, timed search accounting, save compatibility and existing rules/presentation regressions. Source and binary fingerprints matter: evidence is tied to the tested DLLs.

The 1.3.2 final-settlement repair remains: mandatory final liquidation is finished in the isolated afterstate before comparing terminal utilities, without advancing future ordinary turns. V3 has its own cash/reliability qualification and explicit generated-v2-save compatibility tests. Version 1.4.2 reruns the managed rules and native Unity suites because the presentation/persistence helper changed.
