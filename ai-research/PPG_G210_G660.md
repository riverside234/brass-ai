# g210-style PPG continuation from g660

This is an explicit **PPG-only** revision for
`joint7-v11-2-grouped-lr-critic`, starting from committed generation 660.
The final user corrections retain **max_epochs=3**, not six, and check exact
policy KL every **32** optimizer steps instead of g210's every-step checks.

## Effective recipe

The source of the restored semantics is the g210 `recorded-config.json` and
the per-iteration `value_phase.fit`/`actor_value` path at commit `350c92c`.
The g210 export still enabled PPG; the g213 export had already disabled it.

| Setting | New continuation |
|---|---|
| Config contract | `ppg-value-phase/14.0.0` |
| Frequency | Every iteration, immediately after PPO |
| Critic training | Current + previous committed iteration, equal row weights |
| Validation | Current iteration only; g210 stratified 5% whole-game split, at least 2 games per represented table type when feasible |
| Epoch ceiling | 3, fixed; shuffle training rows each epoch |
| Value batch | 4,096 |
| Cloning | Up to 8,192 deterministic current non-forced learner rows; 512 draws per optimizer step |
| Reference | Frozen post-PPO raw temperature-1 legal-action distributions, no exploration mixture |
| Policy guard | Exact KL on the current PPO-selected probe; 2,048 requested rows, all eligible rows if fewer |
| Hard cap | 0.002; exact checks every **32** attempted value optimizer steps, plus short epoch tails and unchecked retained checkpoints |
| Loss checks | Every 16 steps and at each short epoch tail |
| Acceptance | Composite row-mean held-out loss must not increase from the previous accepted state; no SE tolerance |
| Rollback | Restore core weights, value Adam, local scoring heads and their PPG Adam together |
| PPG Adam | Retain moments across phases, as g210 did; no phase reset |
| Learning rate | Constant within a phase: **0.65 × that iteration's last actually applied PPO LR**; changes with PPO across iterations; no PPG warmup/decay |
| Beta | Initial **4**, allowed range **1–32**, changed only for subsequent phases |
| Storage/preparation | Dense FP32 mmap; existing four PPO preparation workers and vectorized ownership-label preparation |

Cloning and policy probes use the current live learner dataset, as in g210;
there are no historical-age policy caches or separate age-0/overall guards.
The critic validation partition excludes whole game/branch families from fresh
value fitting. It does not remove their existing PPO actor use or change g210's
current-learner cloning selection. Snapshot/bot decisions do not enter cloning.

The original beta increase rule is retained: record the last five phase KL-trip
flags; **double beta if this phase trips the hard guard and at least three of
those five flags are true**. A clean phase does not re-escalate on old hits.
After a phase with accepted steps and no KL trip, halve beta when retained probe
KL is **strictly below 0.001**. Empty or fully rejected phases do not use their
zero retained drift to lower beta. Bounds clamp to 1 and 32. There are no
within-phase beta retries.

Loss checks at 16 steps can provisionally accept a checkpoint before its KL
has been measured. A guard trip restores the latest loss-accepted checkpoint
whose exact KL is safe. Pending checkpoints are verified newest first, with
matching value/auxiliary Adam restored. A loss-rejected interval also verifies
the earlier checkpoint it returns to: a safe KL at step 32 does not prove that
the different step-16 weights were safe. No unchecked weights are retained.
Intermediate optimizer steps can exceed the cap between checks; this is a
periodic acceptance safeguard, not a guarantee on every intermediate step.

Only `value_phase` changes in the exported g660 configuration. Existing PPO
value-preservation/DCPG remains active; this does **not** restore g210's older
PPO fresh-target critic fitting. Model layout, policy collection, rewards,
opponents, exploration, branch settings, GAE/snapshot state, warmup, PPO LR
controller, model/Adam/RNG state, completed games and checkpoint lineage stay
unchanged. Ownership heads remain active, with their existing independent
configuration and optimizer; their accepted/rejected work is transactional with
the core critic.

## Adoption and restart

The config helper validates the exact committed checkpoint and reviewed source
transition, then writes only the requested config file. It does not alter the
training run. The actual trainer adopts the new recipe under its run lock.
Beta resets to four **once** when migrating from the old recipe. A subsequent
checkpoint/restart restores its saved beta and five-trip window exactly.

The changed holdout protocol invalidates the old auxiliary caches. Startup
retires only owned PPG caches **after** reviewed adoption has been committed.
An interruption between adoption and the next checkpoint can safely repeat
this cleanup. The first new phase is **g661**, with current data only; from
**g662**, two fresh ages are available. Expired new caches are deleted only
after checkpoint/state commit. Production checkpoints and fixed probes are
not deleted or overwritten by this implementation work.

From the repository root on the training machine, continue **g661–680**:

```bash
python scripts/recover-step5-iteration.py --root "$PWD" \
  --run artifacts/step5/joint7-v11-2-grouped-lr-critic \
  --expected-iteration 660 --apply && \
python scripts/configure-ppg-g210.py \
  --run artifacts/step5/joint7-v11-2-grouped-lr-critic \
  --expected-generation 660 \
  --output configs/step5/joint7-v11-2-grouped-lr-critic-ppg-g210-g660.json && \
python scripts/step5.py \
  --config configs/step5/joint7-v11-2-grouped-lr-critic-ppg-g210-g660.json train \
  --run artifacts/step5/joint7-v11-2-grouped-lr-critic \
  --imitation-run artifacts/step5/features4-v11-2-batch7-il \
  --resume-reviewed-source --expected-generation 660 --iterations 20
```

The completed IL directory is unchanged. A generation mismatch aborts rather
than rewinding. Recovery handles any interrupted uncommitted iteration before
the source/config transition; it is not a rollback to an older generation.

## Validation

The isolated CPU smoke used three tiny authored PPO/PPG iterations with branch
and snapshot rows, ownership heads, dense caching and four preparation workers.
Every iteration ran PPG; accepted steps were **3, 6, 6**, with **108, 217, 218**
critic training rows. Beta followed **4 → 2 → 1 → 1**. The current-only validation
loss decreased in each phase; the probe contained **121** eligible decisions,
so this smoke does not claim production-scale 2,048-row coverage.

Restarting after iteration two reproduced iteration three's core/auxiliary
weights, PPO/value/auxiliary Adam, RNG, beta/trip window and gate state exactly.
Generation-one cache expiry occurred after the third commit. The input
checkpoint checksum stayed unchanged. Wall time was **39.60 s**, including
startup and repeated restart work; phase times were **2.24, 3.19, 3.21 s**.
Results: `artifacts/ppg-g210-g660-kl32-smoke/report.json`. These small phases
finish before step 32, so the scheduled step-32 guard and pending-boundary
rollback are exercised separately by the focused regressions.

Focused tests cover g210 option parity, beta boundaries/three-of-five feedback,
actual PPO LR/no-update handling, one-time adoption and restart, strict loss
rollback, hard-KL rollback including auxiliary heads, cache cleanup and config
helper rejection of unrelated edits. The KL-cadence revision passed **19/19
focused regressions**: eight transaction/cadence tests in **109.21 s** and
eleven configuration/continuation/gate tests in **40.98 s**. Results are recorded
in `artifacts/ppg-g210-kl32-guards.log` and
`artifacts/ppg-g210-kl32-continuation.log`. Tests cover periodic checks across
epoch boundaries, short tails, safe and unsafe provisional checkpoints, and
the case where a safe later probe cannot certify an earlier restored state.
Before the cadence correction, the broader 32-test focused suite also passed;
its record is `artifacts/ppg-g210-g660-final-tests.log`.

An exploratory legacy regression run also encountered two pre-existing stale
fresh-default assertions: one expects exploration 0.02 and another expects
PPG contract v7, while the existing fresh default is exploration 0 and PPG v13.
This PPG-only opt-in does not change those defaults. Three other failures in
that exploratory run requested historical g110/g185/g460 direct-to-current
source routes that are not approved. This change carries forward the 38 routes
already approved to the previous current source and adds the narrow g660
transition; it does not fabricate approvals for unrelated historical recipes.
The final focused suite checks the requested g660 transition and the preserved
g650 helper, as well as the relevant loss/KL transactions and current DCPG path.

Running PPG every iteration can cost more wall time than the prior every-eight-
iteration recipe, despite the smaller replay. The 32-step KL cadence reduces
probe overhead compared with g210's original per-step checks. Epoch tails and
retention checks add bounded extra probes. Strict loss acceptance can still retain zero steps.
The smoke validates mechanics and continuation, not production GPU throughput,
training stability or playing strength.
