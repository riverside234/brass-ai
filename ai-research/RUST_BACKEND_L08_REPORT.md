## Implemented boundary

`native/brass-ai-core/src/features/` implements the frozen Features-4 encoder,
including FE1/FE2/FE3 public accounting and all known/applicable/bound fields.
The typed API produces **3,128 state values and 327 values per legal candidate**,
the complete legal mask, candidate ordering, stable-to-relative seat mapping,
personality tail, remaining utility budgets and v11.2 critic descriptors.
It consumes the acting seat's permitted observation; it cannot read other hands.

The generated [layout metadata](../native/brass-ai-core/data/feature-layout.json)
pins feature order/scales, source identity and the model's grouped/entity gathers.
The model retains those existing gathers internally. No folded representation,
new network architecture, checkpoint conversion or weight change is involved.
The generator imports and verifies the immutable L01 Python sources; its `--check`
mode detects drift without rewriting the candidate metadata.

The implementation prepares public facts/connectivity once per decision, uses
fixed indexed fact storage and reuses tensor/candidate buffers. Card-equivalent
actions share their 143-value derived consequence block while keeping separate
policy rows and exact card-count features. Cache statistics measure this
within-decision effect reuse. There is no persistent feature or NN-result cache
in L08, so changing a model/profile/reward identity or utility context cannot
reuse an earlier result. L10/L11 must implement their separately keyed NN cache.

`FeatureEncoder::encode` returns borrowed native buffers for the future evaluator.
It checks cancellation during preparation/encoding and before publication;
failures invalidate the published result. Positive money is widened for quoted
financial calculations so a valid i32 cash balance plus proceeds cannot overflow.
Protocol, hand-count, public bounds, schema vocabulary, semantic IDs, duplicate
choices, context ranges and descriptor roles are checked before publication.

The diagnostic `features` capability exposes `encode`, `from_state` and `page`.
`from_state` obtains the permitted view and full legal set directly from an
owner-local simulator handle and revision. Python does no feature construction
on that path. Paged transport preserves all candidates while respecting the
1 MiB frame bound; each page carries its encoding ID, total count, offsets,
observer/revision, model context and layout identities. New or failed preparations
invalidate old pages. The Python reader validates ordering and retires a worker
that returns malformed tensors. This transport is a parity tool; native inference
will consume the borrowed buffers without JSON.

The worker retains **two independent one-thread sessions**. There is no extra
inference pool, changed game setting, live backend switch or lab operation.
See the [feature contract](../configs/contracts/rust-backend/features-v1.md).

## Qualification

The final run uses an isolated L01 source tree and separately identified native
client overlay. Captured C# views/choices/states from L05/L06 provide the corpus;
they are not regenerated by the candidate encoder. Root and sampled-world/future
inputs cover both eras, every acting seat and action/payment/continuation/bonus/debt.
Repeated identical view/choice pairs are compared once. Full legal sets are kept.
Held-out fixtures participate in correctness checks; benchmark fixture selection
uses development data only.

The full input corpus runs in debug and release. The profiling build runs a
100-position input smoke check; it does not reuse the release result as a claim
of full profiling-build coverage. Prior L07 complete-game/rules evidence remains
historical; the table lists the regressions actually rerun for L08.
The 40 cyclic-seat cases are explicitly authored transformations of captured
permitted observations, including matching tile identities and budgets. They
supplement the captured corpus where bonus decisions originally occurred only
at some seats; they are not additional C# game trajectories.

Exact float32 equality is required for state/action arrays and exact equality for
IDs, masks, mappings and descriptor inputs. PyTorch output tolerance is
`atol=rtol=1e-6`, with the actual maximum difference recorded. Both encodings run
through the same strictly loaded g890 model on CPU with one Torch compute thread.
All root decisions and representatives of each available future era/phase/actor
combination receive policy, win, rank, VP and utility comparisons.

Unknown descriptors and explicit learner/snapshot/IL/rule-bot descriptors use the
existing `[B,4,34]` schema. Tests check relative-seat placement, stable-order
remaining budgets and actor-policy independence. Model/profile/reward identity
changes, stale/foreign pages and malformed inputs/replies have separate process
tests. Labels in L08 do not admit arbitrary model weights; frozen-model loading,
routing and the ONNX runtime remain L09 work.

## Performance scope

Criterion measures full legal-set encoding using the normal allocator, separately
for reused buffers, fresh encoders and native observation/choice construction plus
encoding. The allocation executable measures allocator traffic separately and
checks zero allocations/reallocations after warm-up. It reports effect hits/misses
and tensor capacities. One-time static layout initialization is excluded from the
fresh-encoder measurement and belongs in L09 model/worker warm-up.

Normal-allocator Criterion arithmetic means on this machine (30 samples each):

| Development fixture | Legal candidates | Warm buffers | Fresh encoder | Observation + choices + encoding |
| --- | ---: | ---: | ---: | ---: |
| Initial action, `game-731001-root-000` | 388 | 0.385 ms | 0.444 ms | 0.724 ms |
| Dense action, `game-731003-root-004` | 413 | 0.411 ms | 0.467 ms | 0.924 ms |
| Complex Rail payment, `game-731009-root-026` | 1 | 0.034 ms | 0.040 ms | 0.130 ms |

The Rail fixture is dense in board/history state, with a forced payment choice;
its single candidate is not presented as a wide action-set benchmark. The dense
action fixture provides that separate measurement. Raw estimates and confidence
intervals are saved in the [Criterion evidence](../artifacts/rust-backend/20261025-l08-qualified-v3/criterion).

All three warm encoding probes performed **zero allocations and reallocations**
across 100 encodes each. This excludes construction of the input observation and
semantic choices, which still costs 3,533 / 4,340 / 1,197 allocations per position
for initial / dense / complex, respectively (plus their recorded reallocations).
Those materialization costs remain visible optimization work for later native
search. The effect cache records hits/misses of 325/63, 331/82 and 0/1 for the three
fixtures. Across the full corpus it avoids 100,121 duplicate derived-action
calculations, while computing 27,581 distinct effects; full policy rows remain.

These are encoder microbenchmarks. They do not measure NN inference, Gumbel search,
two-session search throughput or the matched **four-second whole-turn** comparison.
ONNX/inference remains L09; Gumbel search and its scheduler remain L10–L12. The
4/8/10/12-second settings and local-before-lab migration order remain unchanged.

## Reproduction

Run with the project's Python/dependency environment and pinned offline native
toolchain, choosing a new evidence directory:

```powershell
python scripts/qualify-rust-features.py --out artifacts/rust-backend/<new-l08-run>
```

The script verifies preservation, creates the immutable reference, checks generated
metadata/formatting/Clippy, runs native and process tests, compares corpus and model
outputs, profiles encoding, then archives sources/binaries and writes a qualification
receipt. It never modifies installed game assemblies, saves or model files.
The supplemental [utility/rotation harness](../artifacts/rust-backend/20261025-l08-final/check_utility_context.py)
and [final receipt verifier](../artifacts/rust-backend/20261025-l08-final/verify.py)
are preserved with their own hashes and target the recorded qualification directory.
