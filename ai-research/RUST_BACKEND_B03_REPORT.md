Default search is search_v1; V205 stays disabled. The source supplement and [lab commands](../distribution/rust-lab-b03/README.md) are under `distribution/rust-lab-b03/`.

## Replay and preparation

`rust_backend/lab_admission.py` introduces `four-seat-native-replay/1.0.0` and `brass-native-admission/1.0.0`. The scheduler freezes the job, model/policy, producer/build/B01 identity, feature compatibility, reward, descriptor generation and ordinary/diagnostic scope. Publication keeps the original complete B02 family and recorder evidence unchanged. Reading requires the independently bound writer receipt as well as the sealed family; a family cannot admit itself by changing its header.

The adapter reuses B02's behavior probability, legal choice, per-seat RNG, policy assignment and whole-family checks. Native local-scoring evidence retains `rust-local-scoring/1.0.0` with a separate typed producer. Reference-routed V4 tables retain the C# recorder and runtime hashes. Legacy replay cannot be used to relabel native scoring envelopes. search_v2, composite profiles, V205, ordinary teacher rows, partial/changed/duplicate families, stale descriptors and foreign sources are rejected. The diagnostic first-eligible branch override is never ordinary training data; production branch admission replays the frozen trigger schedule.

Existing checked encoders, replay feature caches, compact parallel ingress, preparation and critic buffers are reused. Native admission receipts travel in retained-cache source metadata, so source reconstruction still passes strict ingress. Old reference critic cache ages keep their original receipts and can coexist with a newly admitted native age without a schedule reset. Same-weight snapshot policies remain critic-only; policy identity determines learner action eligibility. Teacher rows pass through the separate B02.5 improved-policy validator and do not become ordinary games.

## Continuation and diagnostic fork

`rust_backend/lab_continuation.py` builds the target signature from the **actual saved recipe** and changes only its reviewed implementation identity. Preflight checks the caller's expected generation/checkpoint hash, committed source binding, all checkpoint parts and required dependencies. It rejects pending old-source work, weights-only input, reward/recipe adoption mixed into the backend transition and missing/changed committed dependencies. Existing review routes retain their narrow historical config permissions. `resume.py` also validates each intermediate source transition instead of accepting a hash chain without a review.

The sealed inventory includes original state/checkpoint bytes, live population/anchor/PFSP references, committed PPG arrays/metadata/local-scoring sidecars, probe arrays and validation sources, active policy-anchor evidence, persisted rating evidence and teacher ages when present. Retired rating-agent metadata may refer to intentionally retired weights; live evidence remains mandatory. Disposable `il-kl/.prepared` output and unknown files are not copied or deleted. All persisted state fields and checkpoint parts have comparison digests.

The isolated fork records an explicit, sealed origin-to-copy path map. Original `training.fresh_run` and checkpoint bytes remain unchanged. `load_resume` accepts that map only through the verified diagnostic capability, checks the original run binding and resolves pinned dependencies inside the copy. Normal training refuses the fork, whose source state is deliberately named `source-state.json`. This prevents accidentally treating the copy as a new run. No optimizer update or production source-transition commit occurs during qualification.

Restoration uses the real learner, PPO/value optimizers, both local-scoring optimizers, RNG, PPG schedule/beta/cache/controller state, fixed probe, exploration, PFSP, IL-KL and persisted gate/teacher state. Existing signed snapshot-controller overlays retain their validation path. Source-dependent utility readiness may be invalidated under the existing rule; utility weights are preserved and the local g890 exception is not applied. Optional completed-IL handoff is validated separately and cannot substitute for established-run restoration.
