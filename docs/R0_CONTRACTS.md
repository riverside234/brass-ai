# R0 reference pins and project contracts

R0 is implemented locally as version `0.1.0`. This package pins the selected
references, maps their components to project interfaces, and tests the interface
shapes and four-player value semantics. It is not a rules host, playable AI,
trained model, or OpenSpiel game adapter. See the [exit-check record](R0_EXIT_CHECKS.md).

## Files and reproducible checks

| Artifact | Purpose |
| --- | --- |
| [Reference lock](../configs/references/upstream.lock.json) | Immutable commits, Git tree IDs, selected file lengths, SHA-256 and Git blob hashes, license/notice paths |
| [Component map](../configs/references/components.json) | Ten source-to-contract mappings, scalar/seat/hidden-state/two-player assumptions, required adaptations and later-stage owners |
| [Contract schema](../configs/contracts/v0.1.0/wire.schema.json) | Closed JSON Schema 2020-12 message types, with exactly four players |
| [Contract manifest](../configs/contracts/v0.1.0/manifest.json) | Content signatures binding this schema, rules profile, source lock and component map |
| [Rules profile](../configs/rules/steam-brass-patch-1.1.0.json) | Exact installed patch pair, stock provenance, standard-game scope and remaining R1 gates |
| [Python validator](../src/brass_ai/contracts.py) | Structural checks plus cross-message, seat, value, result and budget consistency |
| [Multiplayer prototypes](../src/brass_ai/multiplayer.py) | Original small arithmetic fixtures for acting-seat selection, backup and chance expectation |
| [Verifier](../scripts/verify-r0.py) | Offline metadata checks, explicit optional reference fetching and read-only installed-file checks |

Use Python 3.10 or newer in an isolated environment. The executed checks used
Python 3.12.14 on Windows; Linux has not been executed here. Install
[the pinned validation dependencies](../requirements-r0.txt) into that environment.
No Torch, GPU, Unity process or OpenSpiel installation is needed for R0:

```sh
python -m pip install -r requirements-r0.txt
python scripts/verify-r0.py
python -m unittest discover -s tests/R0 -p "test_*.py" -v
```

The default verifier and unit tests need neither network access nor game files.
The following checks are explicit opt-ins:

```sh
python scripts/verify-r0.py --fetch-references
python scripts/verify-r0.py --check-cache
python scripts/verify-r0.py --game-root "/path/to/Brass Birmingham"
```

The fetcher reads only commit-pinned raw GitHub files into
`artifacts/r0-references`. It verifies both hashes and length before accepting
downloaded bytes. Existing mismatched files cause failure rather than silent
replacement. It never executes or installs reference code. The game check reads
the two declared DLLs without loading them, applying a patch, or opening saves.
All downloaded source, tool packages, logs and game binaries stay excluded from Git.

## Version and compatibility rules

Every environment-facing message carries `compatibility`, except action/turn
plan fragments, which inherit it from their enclosing request/response. This
header identifies the contract version and signature, rules profile and
signature, action schema, feature schema, objective and player count.

For the JSON manifests and observation IDs, a signature is SHA-256 of parsed
JSON serialized with sorted object keys, compact separators, ASCII escaping,
no NaN/Infinity and no trailing newline. This makes whitespace and CRLF/LF
changes immaterial. Reference-source hashes instead cover exact upstream bytes.

Do not edit a released contract in place when fields or meaning change. Create
a new contract version, regenerate its manifest/examples after review, and
reject mismatched producers/consumers. A new patch binary pair requires a new
reviewed rules profile and compatibility signature; a version label alone is
insufficient. The initial manifest is deliberately checked rather than silently
regenerated by `verify-r0.py`.

`unencoded/0.1.0` means no tensor encoder exists yet. The model-metadata fixture
describes a future four-seat output shape; its dummy weight hash is not a model.
R2 must introduce a real feature schema and matching training/export metadata.
Likewise, `trusted_checkpoint.restore_format` is explicitly
`unimplemented/0.1.0`; R0 supplies no restoration implementation.

## Message boundaries

| Contract | Information and semantics |
| --- | --- |
| `player_observation` | One observer's public state, own hand and permitted remembered events. A digest covers that view, never an omniscient checkpoint. |
| `legal_choices` | Choices for a specific observation/context; stable semantic IDs are distinct from model batch indices. |
| `action_plan` / `turn_plan` | Ordered phase-choice IDs for one complete action, or one/two actions within the remaining ordinary turn. Liquidation is separate. |
| `decision_request` / `decision_response` | Actor view, policy/profile identity, game/turn/decision/revision IDs, one remaining turn budget, and a candidate plan or explicit cancellation/failure. |
| `value_prediction` | Four first-place shares, expected averaged placements and auxiliary final VP values, all indexed by stable seats `[0,1,2,3]` and derived from one observer. |
| `terminal_result` | Four players' actual VP/income/cash, competition ranks and equally split first-place shares for complete ties. |
| `model_metadata` | Exact compatibility and reference pins, four-seat head names and a weight hash. No scalar-checkpoint conversion is allowed. |
| `host_reset` / `trusted_checkpoint` | Trusted-host-only environment seed and checkpoint descriptor. Neither is a policy observation. |
| `belief_request` | Allowed observation plus independent search randomness and a world count; no real opponent-hand/deck allocation. |

Stable seats identify players throughout a game. `turn_order` is a separate
permutation. `actor_seat` can differ from `turn_owner_seat` during liquidation.
`actions_remaining` includes the ordinary action currently being planned or
continued; it is zero for standalone liquidation. Opening Canal turns use one
ordinary action, as supplied by the future host. At continuation/bonus boundaries,
an action plan contains only the outstanding choices, not already executed ones.

The public-state fields are an initial typed observation vocabulary, not a
complete verified export from the game. `catalog_sha256` will identify the
public rules/component catalog built and checked in R1. R1 must extend/version
this schema where complete action/phase coverage requires more state. No generic
engine object or unrestricted extension dictionary may be passed through.

Official result ranks use shared competition ranks: a tie for first gives
`[1,1,3,4]`, not `[1,1,2,3]`. The learning `expected_rank` head instead uses
averaged occupied places for ties, so the corresponding targets would be
`[1.5,1.5,3,4]` and the four expectations sum to ten. The initial utility is
`win-share/1.0.0`. A win/placement mixture needs a distinct objective ID; it must
not silently reuse this objective. VP estimates may be negative and are auxiliary.

Both ordinary actions share `turn_budget_id` and `total_ms`. Later requests can
only decrease `remaining_ms` and, in fixed-work mode, `work_limit`. The future
coordinator must enforce elapsed time with its own monotonic clock; a worker's
`elapsed_ms` does not prove timeliness. R0 validates declared budget consistency,
not runtime cancellation or responsive UI behavior.

## What the fixtures establish

The closed schemas reject explicit opponent-hand/deck/checkpoint fields in
observations, inconsistent versions, malformed values and stale response
identities. They do **not** prove information noninterference: IDs, candidate
ordering, event visibility and otherwise permitted field contents still need
R1's counterfactual tests against actual engine states. Only the first returned
choice can be checked against the current offer in R0. Subsequent choices and
resource payments require the R1 host's isolated full-plan validation.

`multiplayer.py` independently prototypes the n-player semantics observed in
the pinned OpenSpiel files: select the acting player's utility, retain all four
returns, and never negate a value simply because play advances. Its tiny chance
fixture computes an exact weighted expectation; this is not OpenSpiel's sampled
MCTS solver. No upstream algorithm was executed and no hidden-information search
quality is established by these arithmetic tests.

The [synthetic message examples](../tests/R0/fixtures/messages.json) have dummy
catalog, model and checkpoint hashes. They demonstrate wire shapes only; they
are not legal saved games, opening advice, training examples or playable plans.

## Handoff after R0

The installed `steam-brass-patch-1.1.0` fingerprints match the bug-fix agent's
record. Its [existing validation](LOCAL_PATCH.md) is reused as evidence, not
claimed as newly rerun by R0. Full runtime dependency fingerprints, rules-host
construction, legal choices, reconstruction and engine-backed privacy tests
remain R1. R0 has not changed or reinstalled the game patch. Legacy opponents,
neural training and the OpenSpiel adapter remain later work.
